# cairn 词汇表

括号内为代码、配置和输出中使用的标识符。

## 文控

**受控资产**
：在资产登记表中有登记记录的文件。

**资产登记表**（registry）
：项目级的受控资产清单，记录每项资产在本项目中的属性：ID、类型、路径、状态、适用范围和完整性校验值。登记不等于批准。

**文件 meta**（meta）
：受控 Markdown 文件开头的 YAML frontmatter，记录文档自身的属性：ID、类型、修订和对外关系。文件不记录自身的接受状态。

**正文标记**
：正文中形如 `@rel(ID)` 的关系声明，与文件 meta 中的声明同为显式声明。

**稳定 ID**（id）
：受控资产的唯一标识。文件改名、移动或修订时，ID 保持不变。

**文档类型**（type）
：受控资产的类别，由元模型定义，例如 requirement、decision、design、specification、verification、standard、reference、glossary。

**文控状态**（status）
：资产在项目中的生命周期阶段，记录在登记表中，是项目属性而不是文档属性。取值如下：

- `draft`：已登记，尚未被项目接受。
- `active`：已被项目接受，现行有效。
- `superseded`：已被其他资产取代。通常由 cairn 推导，不必手工登记。
- `archived`：已退出使用，仅作留存。

**有效状态**
：cairn 采用的状态。存在一份 active 文档声明取代本文档时为 superseded，否则取登记表中的状态。

**修订**（revision）
：资产内容的版本号，记录在文件 meta 中。内容发生实质变化时递增。

**适用范围**（scope）
：资产在本项目中适用的产品、子系统或部件，是项目属性。

**取代**（supersedes）
：新资产替代旧资产，由新资产声明。新资产被接受后，旧资产的有效状态为 superseded；旧资产保留在仓库中，内容不变。

**修订补充**（amends）
：新资产修改旧资产的一部分，旧资产仍然现行，阅读时须与新资产叠加。

## 图结构

**节点**（Node）
：图中的一项受控资产。

**边**（Edge）
：两个节点之间的一条有向关系，从源节点（src）指向终点（dst）。

**来源**（origin）
：一条边的出处，记为 `文件:行号`。同一条边可以有多个来源。

**上游 / 下游**
：从某个节点看，它的出边终点是上游，它的入边起点是下游。

## 关系语义

**元模型**（metamodel）
：cairn 自带的受控定义，规定文档类型和关系类型。项目可以追加类型，不能改写已有类型的语义。

**关系类型**（rel）
：边的语义，例如 supersedes、amends、satisfies、governed_by、depends_on、verifies、related、mentions。每种关系类型由它的形状、两端允许的文档类型、失效语义和视图定义。

**形状**
：关系有向（arrow）还是无向（line）。arrow 从较晚写成的文档指向较早的文档；line 不区分两端。

**视图**（view）
：沿某种关系展开和展示的算法，例如链、覆盖、依赖图、邻域。视图由关系类型决定，不同关系可以使用不同视图。

**失效语义**
：终点发生变化（被取代、修订前进）时，指向它的源文档需要做什么，例如复审、标记为过时、重做验证。`check` 据此判断哪些文档受到变更影响。

**依据级别**（basis）
：一条边的来源和可信程度，从强到弱依次为：

- `declared`：在文件 meta 或正文标记中显式声明的关系。
- `field`：由兼容层从既有写法（字段行、登记表中的 supersedes）读取的关系。
- `inferred`：根据上下文推断的关系。
- `mention`：普通链接，或正文中出现的 ID。

**取代链**
：沿 supersedes 关系连接起来的一串节点，从最初的版本一直到现行版本。

## 抽取

**映射配置**（config）
：某个项目专属的规则，规定登记表的位置、ID 的格式，以及兼容层中字段名到关系类型的对应关系。

**兼容层**（compat）
：读取已有文控仓库既有写法的抽取规则。它让 cairn 能用于尚未采用文件 meta 的仓库，但不是模型的设计前提。

**字段行**
：文档中"字段名加值"形式的一行，例如 `**需求依据**：XX-REQ-001`。由兼容层读取。

**未解析链接**
：指向未登记路径的 Markdown 链接。

## 检索与校验

**工程知识截面**
：针对一个问题，从仓库中取出的一组相关文档，附带它们之间的关系、文控状态和来源。

**现行范围**
：有效状态为 draft 或 active 的节点集合，是 `ls` 的默认范围。

**追溯**
：从一项资产沿受控关系，到达与它相关的需求、决策、规范或验证的路径。

**未建立追溯**
：没有找到明确追溯关系的状态。它表示关系没有被声明，不说明工程事实本身。

**发现**（finding）
：`check` 输出的一条记录，包含 code、级别、节点、来源和说明。级别分为 E（错误）、W（警告）、I（信息）。

## 工具

**派生视图**
：由受控资产计算得到的产物，例如内存中的图和命令输出。可以随时删除后重建。

**确定性重建**
：相同输入总是产生逐字节相同的输出，在不同平台上也是如此。

**完整性校验值**（sha256）
：受控文件内容的 SHA-256。文本文件先把 CRLF、CR 统一为 LF 再计算；LFS 指针取其 oid；二进制文件按原始字节计算。

**合成样例**（fixture）
：为测试构造的虚拟文控仓库，不包含真实业务内容。

**预期输出文件**（golden）
：提交在仓库中的一份命令输出，记录在 fixture 上应当得到的结果。测试时运行命令，把实际输出与它逐字节比较，不一致即失败。行为有意改变时，重新生成该文件，并在评审中检查它的差异。
