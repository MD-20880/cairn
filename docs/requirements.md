# cairn 需求

cairn 是面向 Git 文控仓库的只读检索与追溯工具。需求按条目编号，编号一经发布不复用。

## 定位

- **R-01** cairn 确定性地查找文档、沿受控关系展开，输出带来源的工程知识截面。
- **R-02** 首要目标是真实辅助个人的开发管理。
- **R-03** 查找与追溯由 cairn 确定性完成；大模型只用于理解自然语言问题和总结证据。
- **R-04** 工具成熟后，可以按版本交付给具体项目，作为正式管理工具使用。

## 数据权威

- **R-05** 受控文档始终是事实来源。cairn 的一切产物都是派生视图，可以删除后重建。
- **R-06** 文档的 ID、类型、状态、路径和适用范围以资产登记表为准；正文以原始文件为准；文档之间的语义关系以文档内的声明为准。
- **R-07** 相同输入产生相同输出。
- **R-08** cairn 不修改目标仓库中的任何受控资产。

## 关系

- **R-09** 关系语义受控，每种关系类型有明确方向，类型集合可以逐步扩展。
- **R-10** 显式声明的关系、推断的关系和普通引用分别标识。普通 Markdown 链接只作为引用，不解释为工程依赖。
- **R-11** 强制性约束检查只使用显式声明的关系。
- **R-12** 反向关系由 cairn 自动生成。
- **R-13** 关系以文档为粒度。

## 检索

- **R-14** 支持按文档类型、关键词和文控状态检索。
- **R-15** 返回命中文档上下游各一层的关系。
- **R-16** 结果包含文控状态、修订、适用范围和取代历史，区分历史方案、已批准的决策和待批准的文档。
- **R-17** 每条结果附带关系来源和原始文件位置。
- **R-18** 找不到明确追溯关系时，报告"未建立追溯"。

## 校验

- **R-19** 检查以下各项：引用的 ID 存在；关系类型合法；关系两端的文档类型符合约束；没有不合理的循环；现行文档不指向已取代的依据；关键需求有下游追溯；历史文件未被修改。

## 输出与集成

- **R-20** 提供只读命令行，所有命令都提供可供 agent 调用的 JSON 输出。
- **R-21** 每个命令的语义有明确定义，包括 `ls`。

## 范围边界

- **R-22** cairn 仓库只包含与具体业务无关的内容：模型、工具和合成样例。
- **R-23** 具体项目的映射配置和索引属于该项目。
- **R-24** 模型可以复用于其他文控仓库。
- **R-25** cairn 自身的文档按同一套文控方式管理：资产登记表、稳定 ID 和受控关系。
