# cairn 需求

cairn 是面向 Git 文控仓库的只读检索与追溯工具。需求按条目编号，编号一经发布不复用。

## 定位

- **R-01** cairn 确定性地查找文档、沿受控关系展开，输出带来源的工程知识截面。
- **R-02** 首要目标是真实辅助个人的开发管理。
- **R-03** 查找与追溯由 cairn 确定性完成；大模型只用于理解自然语言问题和总结证据。
- **R-04** 工具成熟后，可以按版本交付给具体项目，作为正式管理工具使用。

## 数据权威

- **R-05** 受控文档始终是事实来源。cairn 的一切产物都是派生视图，可以删除后重建。
- **R-06** 属性按归属分两层：文档自身的属性（ID、类型、标题、修订、与其他文档的关系）以文件 meta 和正文声明为准；文档在项目中的属性（路径、是否被接受、适用范围、批准依据、完整性校验值）由登记表对该文档的登记关系承载，以登记表为准；正文以原始文件为准。两层都出现的 ID 和类型必须一致。
- **R-07** 相同输入产生相同输出。
- **R-08** cairn 的查询和校验命令不修改目标仓库中的任何文件。写操作只由显式的写命令执行，并且只新建文件，或只修改文件中由工具管理的字段。
- **R-26** 文档是否被接受，是它在项目中的属性，不由作者在文件中声明。文件中可以保存由工具写入的项目属性副本，以登记表为准。
- **R-27** "已被取代"由关系和接受状态推导：一份被接受的文档声明取代另一份文档时，后者退出现行。
- **R-28** 所有算法在不同平台上行为一致，包括完整性校验值、路径、换行、排序和输出编码。
- **R-35** 批准记录绑定被批准内容的完整性校验值。内容在批准后发生变化时，cairn 报告。
- **R-36** 完整性校验值只覆盖文档内容，不包含由工具管理的字段。

## 元模型

- **R-29** 文档类型是图的基本元素，关系是图的边。文档类型和关系类型构成受控的元模型，两者的集合都可以逐步扩展。
- **R-09** 每种关系类型有明确的形状和语义：有向（arrow）或无向（line）、两端允许的文档类型，以及终点变化时的失效语义。
- **R-30** 关系可以携带内容，例如说明或所依据的章节。
- **R-31** 视图和算法是关系的派生。不同类型的关系可以采用不同的展开和展示算法。
- **R-37** 资产登记表本身是元模型中的一种类型。它与被登记文档之间的登记关系携带该文档的项目属性。同一份文档可以被多个登记表登记。
- **R-41** 登记关系只能从登记表指向非登记表文档；包含关系只能从登记表指向登记表。登记表通过包含关系组合，包含的对象是文件路径，不是文档 ID，文件名不限。
- **R-38** 推导从根登记表出发：根登记表决定节点范围和项目属性，文档之间的关系来自文件。换一个根登记表，即换一个项目视角。

## 关系

- **R-32** 关系可以在文件 meta 中声明，也可以在正文中用标记声明。两种方式都属于显式声明。
- **R-33** 关系由主动方声明：关系的起点是动作的发出方（满足者、验证者、取代者、依赖者），由它在自己的文件中声明。被动方不声明反向关系，反向关系由 cairn 生成。已冻结的文档不因新增关系而修改。
- **R-10** 显式声明的关系、推断的关系和普通引用分别标识。普通 Markdown 链接只作为引用，不解释为工程依赖。
- **R-11** 强制性约束检查只使用显式声明的关系。
- **R-12** 反向关系由 cairn 自动生成。
- **R-13** 关系以文档为粒度。
- **R-43** ID 的格式不作限制，在项目范围内唯一并已登记即可。识别正文中的 ID 以已登记的 ID 为准，不依赖固定格式。

## 检索

- **R-14** 支持按文档类型、关键词和文控状态检索。
- **R-15** 返回命中文档上下游各一层的关系。
- **R-16** 结果包含文控状态、修订、适用范围和取代历史，区分历史方案、已批准的决策和待批准的文档。
- **R-17** 每条结果附带关系来源和原始文件位置。
- **R-18** 找不到明确追溯关系时，报告"未建立追溯"。

## 校验

- **R-19** 检查以下各项：引用的 ID 存在；关系类型合法；关系两端的文档类型符合约束；没有不合理的循环；现行文档不指向已取代的依据；关键需求有下游追溯；历史文件未被修改；文件 meta 与登记表一致。

## 输出与集成

- **R-20** 提供只读命令行，所有命令都提供可供 agent 调用的 JSON 输出。
- **R-21** 每个命令的语义有明确定义，包括 `ls`。
- **R-39** 根登记表是一个文件，默认名为 `cairn.yaml`，文件名可以通过参数更改。cairn 从当前目录向上查找最近的根登记表文件作为根，输出注明所用的根。根登记表由初始化命令创建。
- **R-42** 提供轻量的编辑辅助，例如 VS Code 插件：编辑文档时输入可自定义的触发语法，弹出文档检索，选中后快速写入链接或关系标记。编辑辅助通过 cairn 的检索接口取数，不另行解析仓库。
- **R-40** cairn 的核心功能不依赖 git：查找、读取、推导和校验只使用文件系统。只有读取版本历史的功能依赖 git。

## 范围边界

- **R-22** cairn 仓库只包含与具体业务无关的内容：模型、工具和合成样例。
- **R-23** 具体项目的映射配置和索引属于该项目。
- **R-24** 模型可以复用于其他文控仓库。
- **R-25** cairn 自身的文档按同一套文控方式管理：资产登记表、稳定 ID 和受控关系。
- **R-34** 已有文控仓库的既有写法（字段行、登记表中的取代关系等）通过兼容层读取，不作为模型的设计前提。
